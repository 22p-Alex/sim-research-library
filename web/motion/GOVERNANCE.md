## 修改入口与职责

| 要修改的内容 | 修改位置 | 约束 |
|---|---|---|
| 本幕目的、标题、说明、公式、时长 | 本幕 `storyboard.js` | 一幕回答一个主要问题；公式与说明解释同一步操作 |
| 动作进度、强调顺序、派生读数 | 本幕 `state.js`，若存在 | 相同数据和进度必须产生相同状态；不得读取真实时间 |
| SVG / Canvas 演员及更新 | 本幕 `view.js` 或目录注明的共享模板 | 创建一次，更新属性；隐藏、退出和销毁由所属容器负责 |
| getPeak 的桌面位置与尺寸 | `get-peak/layout.js` | 排版不修改数据、拍内进度或公式意义 |
| 幕的组合和前后衔接 | `scenes/index.js`、`sim-motion-parameter-chapter.js` | 使用稳定 ID，保留已声明的输入与输出 |
| 实际数值算法 | `../shared/sim-parameter-estimation.js`、`../atlas/sim-atlas-core.js` | 必须有本地源码或公式依据，并核对独立结果 |
| 页面加载顺序和共用模板归属 | `../animation-assets.json` | 更新后执行 `npm run scenes:sync` |
| 排练工具 | `../shared/animation/` | 复用宿主播放器，不创建第二个时钟 |

文件按场景归属，不要求每一幕都拥有五个文件。只有文案、公式和简单过渡的幕保留 `storyboard.js`；有独立状态或演员时再增加对应文件。样品、宽场和照明共享图像演员；融合数幕共享三栏模板。共享模板的修改会影响目录中列出的所有使用者。

`sim-motion.js`、`sim-motion-stages.js` 和 `sim-parameter-two-stage.js` 负责接线与兼容 API。新增长段讲解时，先放进场景单元，再由宿主调用。`sim-motion-fourier.js` 是单独打开的八段条纹教学弹窗，仍由弹窗自身单元管理；不计入主线幕数。

## 分镜、动作和时间

复杂场景以“拍”为编辑单位，每拍明确动作、说明、公式及阅读停顿。getPeak 的九个独立停点已经采用 `SIMBeatClock.define`：

```js
{
  key: 'finalSum',
  duration: 17600,
  action: '全场双路累计',
  // title / copy / note / formula 与这一拍放在同一处。
  cues: { sumSweep: [0.227272727273, 0.954545454545] }
}
```

`duration` 是毫秒；`cues` 是本拍的 0—1 进度。改变某一拍时长，不需要重新计算后续拍的全幕阈值。编译器负责计算拍边界，校验唯一名称、正时长和有效动作范围；画面、标题、公式强调读取同一次状态计算。

其他场景已经按幕拆分，保留原有经过核对的动作时序。频率编码、临时分离、评分、FFT 与细化提供内部拍定位；部分旧场景内部仍使用既有归一化阈值或基础时间坐标。这些场景调整内部节奏时，需要同时检查本幕状态和公式。**getPeak、归位、加权、累加与 Wiener 的新分镜已提供“任意单拍改时长而动作不变”的自动契约。**后续改写某个复杂场景时，在该场景内迁移拍内时序，不要求一次重写整条动画。

主播放器只推进一个进度；拖动、倒放和快速定位直接重算状态。绘制函数不自行采集数据、不重新估计参数，也不使用额外 `setTimeout` 或循环推动演员。

## 转场所有权

每幕明确接住上一幕的什么状态、保留什么节点、输出什么状态。跨幕复用的演员由共享模板持有；独立主体放在自己的根容器内，退出时处理整个容器，避免枚举上一幕所有零散节点。

refine→getPeak 的当前实现：先构造已声明的 `refine(1)` 概览，波矢标记和原频谱置于旧主体外独立持有。第 19 幕先连续展开同一频谱演员的原生检测坐标，再在相同槽位交给工作频谱；波矢标记保持到第 24 幕输入就位后。第 23→24 幕复用同一对场图与向量节点，保持样本和共同线性标尺，先移动槽位再共轭。详见[α 入口第一版](plans/2026-10-19-alpha-entry-v1-delivery.md)。退出时交出参数卡片，回填的三个停点读取相同估计结果。

修改转场至少检查：前一幕终点、后一幕入口、交接中间帧和回退后的状态。几何连续性及可见性检查要考虑父容器的透明度，不能只检查节点自身属性。自动状态检查能发现位置突跳、非法数值和幽灵图层；真实字体基线、遮挡和节奏仍需用户在页面验收。

## 公式与数据

公式的定义和强调顺序属于本幕。场景状态决定当前公式、参与强调的符号及可见性，视图只执行绘制。使用 MathML / KaTeX 的既有缓存，复用公式节点；不要每帧重新编译完整公式。

getPeak 的公式拆项和演员读取同一个拍状态，分子、分母、累计计数均来自 `estimate.finalPeak`。搜索用的 `estimate.fit` 与最终幅相工作数组分别保留。前面搜索校正过的频谱不能再次充当最终算法的原始输入。详细数值依据见[源码七拍说明](plans/2026-10-17-fairsim-getpeak-storyboard.md)与[参数章节说明](../parameter-demo/README.md)。

理论依据采用本地 fairSIM 固定提交 `711afd12cb8c4fd4207bbca7ee7610c5aed4f732`。最终 `commonRegion/getPeak` 已有本地 Java 与独立 DFT 对照；前面三轮 5×5 位置搜索仍是教学实现。治理改变代码归属，不扩大算法准确性声明。

## 如何排练和报告问题

1. 在任一动画页点击“分镜排练”，播放器暂停，面板默认折叠。
2. 选择场景和分镜，拖动“拍内进度”查看中间帧；“播放本拍”使用原播放器并停在拍末。
3. 点击“复制定位”。剪贴板不可用时，面板会选中文字，手动复制即可。
4. 报告问题时附上定位码及现象；粘贴定位码再点“跳转”可恢复对应位置。

```text
scene=parameters.least-squares-fit&beat=finalSum&p=0.500000
```

这里 `least-squares-fit` 是旧组合场景的兼容 ID，旧定位码按 beat 转到新的独立停点；例如 `finalSum` 对应 `parameters.get-peak-sum`。九幕共用 `get-peak` 场景目录和一个计算时钟。独立页使用不带 `parameters.` 的 ID。定位码中的 `p` 是所选拍内进度，不是整页时间。实际观测由各宿主初始化，定位码不改变数据或页面入口。

## 新增、删除和验收

新增一幕先写明输入、输出、主要问题、依据、分镜和转场，再写状态与视图。删除一幕需同步清理组合、模板使用关系和加载清单；固定 ID 变更应提供兼容映射。显示幕号由组合顺序生成，不能当作永久标识。

```sh
npm run scenes:sync
npm run check
git diff --check
```

`scenes:sync` 根据清单更新两个 HTML 的本地脚本标签与目录；不启动服务器。`scenes:check` 检查生成物、资源存在性、重复加载和模板归属，已纳入 `npm run check`。两页生产脚本在模拟 DOM 中运行，覆盖定位、播放、回退和公式状态。视觉检查由用户在允许访问的页面完成；不能将模拟 DOM 通过记为视觉通过。
