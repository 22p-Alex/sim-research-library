# 《SIM Motion · 从样品到超分辨重建》评审

对象：`dist/sim_motion_demo.html`（33 幕主线，依赖 `web/motion/*`、`web/parameter-demo/*`）
评审日期：2026-10-18
评审范围：UI 风格、分镜连贯性、fairSIM 讲解实现程度

---

## 0. 总体结论

这是一份**工程完成度与自我约束程度都远高于同类教学页**的作品：数值来自真实管线（非示意）、公式用 MathML、每一步都标了源码行号与文献依据，甚至主动标注"教学实现 ≠ 原版 fairSIM"的偏差。它的问题不在"讲错"，而在**权重分配与呈现层**：

1. 时间预算严重失衡——参数估计链占 76%，fairSIM 的融合重建只占 4.6%；
2. 演示数据是**无噪声**工况，导致 Wiener 正则化与切趾的必要性只能靠文字断言，无法自证；
3. 视觉系统精致但为"近距离屏幕阅读"设计，投影场景下 9–11px 标签与弱对比色会失效；
4. 章间只做透明度交叉淡入，没有"同一对象跨幕连续变形"的硬约束，存在若干记忆断裂点。

## 1. UI 风格

### 1.1 配色

| 色值 | 角色 | 语义一致性 |
|---|---|---|
| `#091115` / `#101b21` | 底 / 面板 | 近黑冷灰，舞台与 UI 同族，无脏灰 |
| `#edf0e9` | 主文字 | 微暖白，避免纯白刺眼 |
| `#efb879` 橙 | 选中分量 q、−1 级、交互高亮 | 一级强调 |
| `#7ad5cd` 青 | 0 级、检测、相位 | 二级语义 |
| `#b7a5eb` 紫 | +1 级、共轭 | 三级语义 |
| `#8b9b9f` 及以下 | 辅助文字 | 对比度不足 |

**结论：这是一套真正的语义配色系统，不是装饰性配色。** 0/+1/−1 三个级次在矩阵行（`.demix-order-rows`）、频带、复数箭头中保持青/紫/橙一致，跨 33 幕没有跑偏——这在自制教学页里很少见，是本页最大的视觉资产。

需要指出的两个问题：

- **橙色一色两用**：既是"−1 级"，又是"+选中/悬停/焦点"（`.edge:hover`、`#pause`、focus ring 全为橙）。当 −1 级频带与悬停态同时出现时，观众无法区分"这是级次标记"还是"这是可点区域"。
- **弱对比文字未达 AA**：`#587078`（`.edition`、计数器 `/33`）、`#637e89`（时间轴标签）、`#5f7a85`（`.equation-label`）对 `#091115` 的对比度约 3.3–3.7:1，且字号只有 9–10px，属"存在但读不出"。

### 1.2 字体

四套字体分工明确且克制，没有出现"一款字体打天下"的廉价感：

| 用途 | 字体 | 评价 |
|---|---|---|
| UI / 正文 | `-apple-system, PingFang SC` | 中性，不抢戏 |
| 数字与算符（`f → q` 64px、页码、RMSE） | Georgia serif + tabular-nums | 编辑感强，与暗底很搭 |
| 公式 | `STIX Two Math / STIXGeneral`（MathML） | **关键优点**：公式是文本不是图片，可选中、可缩放、可被读屏 |
| 数值读数 | `SFMono-Regular` | 表格内列对齐正确 |

### 1.3 排版

- 五段式骨架稳定：`顶栏 70 / 标题区 123 / 舞台 / 公式栏 176 / 走带 102`（1080p 下）。33 幕切换时骨架不跳动，这一点做得很好。
- 标题 `clamp(24–38px)`、导语 `clamp(12–15px)`、公式 `clamp(18–25px)`，三级差足够；`max-width:950px` 控制了行长。
- **但版面过满**：1080p 下舞台实得高度约 500px，而 viewBox 是 `1440×560`，实际按 `meet` 缩放约 0.86，SVG 内 15/17px 文字落到 13/15px。加上 `overflow:hidden` 与 `min-width:960px`，1280×720 投影时会出现"看起来都在、其实读不清"的状态。

### 1.4 控件

- 一律文字按钮 + 1px 发丝线 + 4–5px 圆角，没有渐变按钮、没有阴影卡片，风格统一且克制。
- 细节到位：`focus-visible` 统一 2px 橙描边 offset 5px；`prefers-reduced-motion` 全局降级；`dialog::backdrop` 用 `blur(7px)` 而非纯黑。
- 交互分层清楚：左侧 `←/→` 整屏翻步（默认 `opacity:.22`，悬停才亮，避免干扰画面）；时间轴 33 个刻度常驻；`分镜排练` 面板可定位到"幕 + 拍 + 拍内进度"并复制定位码——这是很专业的排演工具。

**一个需要你本地确认的代码级风险**：`.app` 只定义了 3 行网格（`70px / 1fr / 102px`），而 DOM 有 4 个子元素（header、`#scene-rehearsal`、main、footer）。排练面板 `hidden` 时不参与布局，一旦展开就会成为第 2 个网格项占据 `1fr`，把 `main` 挤到 102px 行。建议：

```css
.app:has(#scene-rehearsal:not([hidden])){grid-template-rows:70px auto minmax(0,1fr) 102px}
```

（我不会开浏览器验收，这条只从 CSS 与 `rehearsal.js` 的 `container.hidden = !visible` 推得，请你在本地点一次"分镜排练"确认。）

### 1.5 信息架构的小瑕疵

- 幕序号 `01–33` 与章序号 `01–08` 两套编号并存，都出现在左/右上角，观众第一眼会混淆。
- 静态文案写"全部 36 个讲解步骤"（`#scene-stops` 的 `aria-label`），页面计数写 `/ 33`，注册表 33 幕。运行时会覆盖 `max` 与总数，但 `aria-label` 不会被覆盖——读屏用户会听到 36。
- "分镜排练""原理与数值""全屏"三者并列在同一 nav，前两者是工具、后者是视图，权重本应不同。

## 2. 分镜连贯性

### 2.1 时间预算（这是最硬的问题）

| 段 | 幕 | 时长 | 占比 |
|---|---|---|---|
| 开场：样品 → 宽场 → 照明 | 01–03 | 3.1 s | 0.4% |
| 编码与检测（含 112 s 欧拉展开） | 04–06 | 123.6 s | 17.0% |
| 三相位观测 | 07–08 | 9.4 s | 1.3% |
| 解混 + 参数估计 | 09–20 | 554 s | **76.2%** |
| 频带归位 | 21–23 | 13.1 s | 1.8% |
| 多方向覆盖 | 24–26 | 5.9 s | 0.8% |
| Wiener 融合 | 27–30 | 13.0 s | **1.8%** |
| 逆 FFT 与验证 | 31–33 | 5.1 s | 0.7% |
| 合计 | 33 幕 | 727 s ≈ 12 分 07 秒 | 100% |

单幕极值：最长 `provisional-split` 132 s，最短 `relocate-bands` 1.65 s，**比值 80:1**。

`provisional-split` 一幕 = 全片 18%；`separate-bands + relocate + recover + 融合四幕` = 26.6 s = 3.7%。也就是说，**fairSIM 最核心的"加权—求和—正则化—切趾"四步，只给了 13 秒**，而"如何把 k̂ 细化到 0.01 格"给了 68 秒。对答辩而言这是比例失当，而不是时长不足。

### 2.3 时间/空间关系的三个具体问题

1. **空间尺度的连续性没有宣告。** 各章使用不同的频率视野（频率面约 48 格视野），但章节切换只有透明度变化，没有"同一把尺"的视觉提示。观众无法判断 04 幕的"±8 格"与 22 幕的"向左 8 格"是否同尺度——虽然数值上一致（k = N/p = 128/16 = 8），画面上却看不出来。
2. **"同一个 f" 的锚点没有跨幕携带。** 06/08/09/10 都围绕"同一个检测频率 f"展开，但每次切幕都重画，f 的游标不常驻。建议给 f 一个跨幕保留的幽灵标记（低透明度、跨 fade 不消失）。
3. **精度表述不统一。** 22 幕说"±8 格"（整数），24 幕说"60.3°"（0.1° 精度）。两者都来自估计，却给了不同量级的精度暗示。若方向 1 的 k̂ 也是估计值，应写"8.00 格"；若确实是整数真值，应在文案里点明"本例方向 1 恰好落在整数格"。

### 2.4 转场机制

代码层面只有一套机制：`motionAlpha / provisionalAlpha / parameterAlpha / adoptedAlpha / pairAlpha` 五个组的透明度交叉（`sim-motion.js:311`），没有相机推拉、没有共享元素过渡、没有方向性位移。优点是不会崩坏、性能稳；缺点是**章与章之间只有"淡出淡入"，观众必须自己重建空间关系**。32 次切换全部走这一套，是"稳"而不是"顺"。

## 3. fairSIM 的讲解实现程度

### 3.1 覆盖清单

| # | fairSIM 要素 | 状态 | 说明 |
|---|---|---|---|
| 1 | 条纹照明模型、三相位采集 | 充分 | 03 幕 + 理论窗，含两束光干涉推导 |
| 2 | 编码三带（欧拉展开 + 移频定理） | 充分 | 04 幕 14 拍逐步推，含 `F{s·e^{±i2πk·r/N}} = S(f∓k)` |
| 3 | 三帧三元线性方程组、逆矩阵 | 充分 | 09–10 幕，显式给出 `u_{0,j}=1/3`、`u_{±1,j}=2e^{∓iφ_j}/(3m)`，并说明伪逆情形 |
| 4 | 参数估计：峰搜索 + 亚像素细化 | **超充分** | 12–18 幕，含 `O(N⁴)→O(N²logN)`、相位斜坡小数移频、三轮 5×5 |
| 5 | 参数估计：共同幅相（getPeak） | 充分 | 19 幕，按 `Correlation.java` 顺序复刻，含最小二乘的代数解释 |
| 6 | OTF 加权 H*、\|H\|² 传递系数 | 充分 | 27 幕，`H*C=\|H\|²S` 与串扰区分清楚 |
| 7 | 全局归一 + w² 正则 | 充分（但缺动机） | 29 幕公式完整，w=0.05 固定 |
| 8 | 切趾窗 | **部分** | 只讲"压低边缘"，未讲抑制截断振铃 |
| 9 | 频带搬移与多方向覆盖 | 充分 | 21–26 幕，单方向/九带/三方向分层清楚 |
| 10 | fairSIM 的计数约定（0 级双计） | 充分但位置隐蔽 | 只在 29 幕 copy 一句 + 理论窗；`R = R₀ + Σ\|H_{d,0}\|²` 的后果讲得很诚实 |
| 11 | 噪声与权重统计意义 | **仅文字** | 理论窗有 WLS 推导与 σ²/λ，主线完全没有画面 |
| 12 | 伪影成因（蜂窝/条纹/振铃） | **缺失** | 仅 11 幕用"参数失配"示范了残余条纹 |
| 13 | 与其他重建路径的对照 | 缺失 | 没有"逐带除 OTF 再平均"的失败演示 |
| 14 | 3D-SIM / 轴向 OTF | 缺失 | 本页定位 2D 九帧，需在开篇声明边界 |

### 3.2 三个"已充分"里最值得肯定的点

1. **27 幕把"已有 H，再乘 H\*"单独拆成一幕**，并在 note 里明确"连同后续归一化，实际融合权重是 g = H\*/(R+w²)，它和解混权重 u 不是一回事"。绝大多数 SIM 教学材料会把这两个权重混成一个符号，这里没有。
2. **29 幕主动承认分母与分子不对称**："分子各频带计一次，分母每个方向对 0 级计两次"，并给出后果 `Ŝ = P_apo·R₀/(R+w²)·S`。这是把实现细节当知识点讲，答辩时是加分项。
3. **32 幕没有粉饰 RMSE 反而变大**，并解释为幅度抑制所致，还提醒"0.2643 ≠ 分辨率误差 26.43%"。这种自我限定在毕业设计材料里非常罕见。

### 3.3 关键缺失：无噪声数据讲正则化

`sim-motion.js:575`：

```js
const capture = A.capture({ sample:'star-points', directions:3, m:.8, noise:'none' });
```

**演示数据是无噪声、m=0.8、无漂移、波矢落在整数格的最理想工况。** 后果是：

- 29 幕"w² 避免传递很弱时产生过大的反演增益"只能是一句断言——画面里没有噪声可放大；
- 30 幕"切趾抑制边缘"同理，画面上看不到振铃；
- 全片无法回答"为什么不能逐带除以 H 再平均"这个 fairSIM 存在的理由。

这一条同时击中你的研究主题（伪影抑制）。**建议把这一条当作 P0 优先级**：不需要新数据，同一份采集加噪声场、或直接给 9 帧叠加泊松/高斯噪声，做一镜"A/B 对照"即可。

### 3.4 表述不清的六处

| 位置 | 问题 | 建议 |
|---|---|---|
| 29 幕 copy | "按 fairSIM 的计数约定累计分母"——"计数约定"是源码黑话 | 改成"fairSIM 在分母把每个方向的 0 级算两次，所以 0 级增益是 1/2" |
| 21 幕 copy | 只说"三份观测乘对应权重"，未点明此处权重已是**估计值**（20 幕刚填回） | 加"用刚才估计的 m̂、φ̂ 代入" |
| 27 幕画面 | 画面只显示 `|H|²S`，最终权重 `g=H*/(R+w²)` 只在 note | 把 g 的表达式放进舞台右侧常驻小字 |
| 30 幕 | 未说明切趾是"抑制截断导致的振铃"，与 07 章主题直接相关却略过 | 加一句"不加窗时边缘会被硬截断，逆变换出现振铃" |
| 29 幕 | w=0.05 未给量纲/尺度（相对 R 的什么范围算大） | 给一条 `1/(R+w²)` 的曲线，标出 w 生效区间 |
| 32 幕 | RMSE 反升的完整解释在 note 与弹窗，主画面只有标题 | 主画面加一行"本例 SIM 的 RMSE 更大，原因是幅度被抑制，不是分辨率变差" |

### 3.5 定位判断

若目标是"讲清 fairSIM 这条重建链"：**8/10**。公式、顺序、数值、源码位置都可核查，且主动标注了教学实现与原版的差异（5×5 vs 10×10、掩膜不同、预处理不同）。

若目标是"讲清 fairSIM 解决了什么问题"：**5/10**。它把 fairSIM 讲成了"一条正确的流水线"，而没有讲成"对一个具体失败模式的回答"。

## 4. 改进建议清单（按优先级）

### P0 — 影响结论正确性，建议答辩前必改

1. **加一镜"无正则 vs 有正则"对照。** 同一份九帧加噪，左：逐带除 H 后等权平均（出现噪声放大 + 蜂窝残余）；右：H\* 加权 + `1/(R+w²)`。这一幕可放在 29 幕之后，8–12 s。这是全片唯一能"自证"Wiener 必要性的镜头，也直接对接你的伪影主题。
2. **重配时间预算。** 目标：参数估计段 554 s → 300 s 以内（`provisional-split` 132 → 50，`refine` 68 → 40，`least-squares` 80 → 55）；把释放的 ≥150 s 给 21–31（`separate-bands` 9.5 → 20，`relocate/recover` 各 → 3.5，融合四幕 13 → 40，`inverse-fft` 1.7 → 3）。
